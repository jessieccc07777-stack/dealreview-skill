# 交付两成果（第 5 步）

> 配套 `SKILL.md` 第 5 步。两份成果共享同一套风险分级与可接受底线，互相对齐。
> 中文为主，关键条款中英对照。

## 总约束（促成交易机制贯穿两成果）

1. **每条风险必带可接受底线**：无底线不交付。结构 `风险 → 可接受底线写法 → 建议交换条件`。
2. **报告必含「建议放行清单（🟢）」专节**：证明非处处对抗，积累谈判信用。
3. **谈判三栏嵌入「谈判建议」段**：「必须坚持 / 可换对价 / 可让步」。
4. **修订条款必须"拿来即用"**：直接可粘进协议的完整措辞，非模糊指引。
5. **每份成果级别一致**：同一条款在报告（五段式）与 redline（是否改）中分级相同。
6. **每条修订必附修订依据**：法律依据（新《公司法》/ 九民纪要 / 判例 / 市场惯例）+ 事实依据（交易结构 / 行业惯例 / 谈判筹码）。

## 成果一：风险审查报告（五段式 + 修订依据）

**生成方式**：md 或 docx，按"高 → 中 → 低（放行）"排序逐条呈现。

**结构**：

```
# 投资协议风险审查报告

## 一、交易概览
协议文件 / 类型 / 轮次 / 投资人类型 / 结构 / 前轮 / 时间压力（来自接件）

## 二、逐条风险审查（按风险从高到低）
【高 · 🔴/🟠】
### 条款 N · 风险级 🔴/🟠
- 风险说明：<协议现表述 + 偏离可接受底线 + 投资人目的>
- 不利后果：<若不改的具体损害>
- 谈判建议：<立场 + 可接受底线 + 交换条件>【三栏：必须坚持 / 可换对价 / 可让步】
- 修订条款（可直接替换原文）：<最终措辞，中文为主 + 关键英文对照>
- 修订依据：<法律依据：新公司法/九民纪要/判例/市场惯例>；<事实依据：交易结构/行业惯例/筹码>

【中 · 🟡】
### 条款 M · 风险级 🟡
（同上五段式 + 依据）

## 三、建议放行清单（🟢 市场惯例 · 已核对放行）
| 条款 | 协议现状 | 核对结论 | 放行理由 |
|---|---|---|---|
| 优先购买权 | 含员工平台例外 | 市场惯例区间 | 放行，积累信用 |
| 信息权 | 按季+保密承诺 | 市场惯例区间 | 放行 |
| ... | ... | ... | ... |

## 四、创始人个人责任四项核查
| 项目 | 现状 | 风险级 | 处理 |
|---|---|---|---|
| 个人连带 | 已改为股权为限 | 🟢已设防 | 放行 |
| 股权质押 | 仅限股权为限份额 | 🟢已设防 | 放行 |
| 个人保证 | 无 | 🟢 | 放行 |
| 配偶共债 | 仅确认函非共债 | 🟢已设防 | 放行 |

## 五、专项扫描结果
（TS偏离 / Side Letter冲突 / 多轮叠加 摘要，详见 special-scans）

## 六、下一步建议
按优先级：先清🔴 → 争🟠（用🟡/🟢让步换）→ 微调🟡 → 🟢整体确认放行。
```

**要点**：报告给创始人/公司决策用，语言克制、给路径不给恐吓；「建议放行清单」必须醒目。

## 成果二：协议修订模式 redline（Word · 修订模式）

**生成方式**：调用 `scripts/redline_word.py`（技术细节见 `references/redline-word.md`）。
将成果一中所有 🔴/🟠/🟡 的"修订条款"以 `(原条款文本, 修订后条款文本)` 对在**客户上传协议副本**上用
Word 修订模式（w:ins 插入 / w:del 删除）落地；🟢 放行条款不动。

**redline 纪律**：
- 🔴：删除/重写（报告写为何不可接受 + 可接受底线）。
- 🟠：改为可接受底线写法（报告写交换条件）。
- 🟡：微调措辞。
- 🟢：不改，仅在报告说明"已核对，属市场惯例，放行"——不消耗谈判火力。
- 仅在用户协议**副本**上操作，**不覆写原件**；最终每项修订由用户在 Word 中接受/拒绝把关。

**中英对照示例**（修订条款段内）：
> 创始人回购义务以所持股权为限。
> Founder's repurchase obligation is limited to the equity it then holds.

**生成步骤（运行时）**：
1. 从成果一抽取所有需修改条款的 `(old, new)` 对（old = 协议原句，new = 报告"修订条款"段措辞）。
2. 调用 `apply_redline("客户协议.docx", replacements, out_path="客户协议_修订模式.docx")`。
3. 检查返回的 `not_found`：若有未定位条款，回报告说明并人工定位，不硬改。
4. 两份成果一并交付：① 风险审查报告 ② 协议修订模式 docx。

## 两成果对齐检查（交付前必做）

- [ ] 每条 🔴/🟠/🟡 在报告（五段式）与 redline（已改）两处一致出现，分级相同。
- [ ] 「建议放行清单（🟢）」在报告中存在，且 redline 中这些条款未被改动。
- [ ] 每条修订均有可接受底线与（或"无，须坚持"）交换条件 + 修订依据。
- [ ] 创始人个人责任四项在报告第四节列明。
- [ ] 关键条款含中英对照。
- [ ] redline 仅落于客户协议副本，未覆写原件。
- [ ] 报告未出现内部操作术语（路由/卡片定位）与模板标记（【专节·必填】等），未臆测用户未提供的轮次或交易信息。
