# 接件确认与协议路由（第 1–2 步）

> 配套 `SKILL.md` 第 1–2 步。触发语常为「帮我审核这一份/几份协议」，用户通常直接 @ 上传一个或多个 docx 协议文件。在动笔审查前锁定坐标，再按协议类型路由到条款卡。

## 一、接件表格（Intake Form）

逐项向用户确认；未提供则以合理默认假设继续，并在交付物中标注"假设项"，不阻塞成交。

| 维度 | 选项 / 填写 | 对审查的影响 |
|---|---|---|
| **协议文件** | 用户 @ 上传的 docx 路径与份数（本次审查对象；redline 将在此副本上落地） | 决定单份还是多份并行、redline 输出份数 |
| **协议类型** | □ TS □ SPA □ SHA □ Side Letter（可多选） | 决定路由到哪些卡片、审查深度 |
| **轮次** | 天使 / Pre-A / A / B / C / 后期 / 并购前 | 早期筹码弱→重个人风险设防；后期筹码强→可争更多 |
| **投资人类型** | □ 国资 □ 市场化财务投资 □ 产业方(CVC) | 国资→明股实债禁令（卡 2）；产业方→可能要业务控制与信息权放大 |
| **交易结构** | □ 境内人民币 □ 境外美元(VIE/红筹) | 美元→英文术语、适用法/仲裁不同（卡 20）、常用 Market Standard 措辞 |
| **前轮协议** | 有/无；轮次与文件清单 | 决定第 4 步"多轮权利叠加"与"TS vs 后续偏离"扫描 |
| **谈判时间压力** | 紧迫/适中/宽松 | 紧迫→先保成交，🟠🟡 中可让步项优先放行；宽松→全力推 🔴🟠 |

**接件确认话术示例**："在审这份 TS 前，我需要确认几点：轮次是 A 还是 B？领投是财务投资还是产业方？境外还是境内结构？有没有前轮 SHA 要衔接？时间上紧迫吗？——这几点决定我帮你争什么、放什么。"

## 二、协议类型路由图（Routing Map）

| 协议类型 | 路由到的条款卡（重点） | 审查着力点 |
|---|---|---|
| **TS** | 全部 20 张卡 | TS 是后续文件的谈判基准；逐条标记"意向上限"，预判 SPA/SHA 会被放大处 |
| **SPA** | 估值/Cap-table(见卡外注)、交割先决、陈述保证(19)、赔偿(19)、回购触发(1/2) | 钱怎么进来、价格怎么算、交割条件、违约赔偿上限 |
| **SHA** | 回购(1/2)、优先清算(3)、反稀释(4)、拖售(6)、随售(7)、优先购买/认购(8)、MFN(9)、限售(10)、一票否决(11)、信息权(12)、董事(13)、不竞争(15)、质押/担保(16)、个人四项(17)、QIPO(18)、争议(20) | 投后治理与特殊权利；个人风险四项必查 |
| **Side Letter** | 主协议对应卡 + 第 4 步冲突扫描 | "抽屉"优惠/例外是否与主协议冲突、造成双重义务 |

> 注：估值与 Cap-table 数学（投前/投后估值、每股价格、投资人持股比、注册资本与资本公积）属 SPA 经济基础，审查时按"投资人持股比 = 融资金额 ÷ 投后估值""每股价格 = 投前估值 ÷ 投前总股本"等公式核验，防止稀释计算被做手脚；该部分不单列卡片，并入 SPA 审查要点。

## 三、多协议并行时的处理

一次交易常 TS→SPA+SHA 并行。处理顺序：
1. 先读 TS，建立"经济条款基准线"。
2. 再读 SPA（进入机制）与 SHA（治理与权利），逐条与 TS 基准比对。
3. 最后读 Side Letter，单独做冲突扫描（第 4 步）。
4. 两份成果（风险审查报告 / 协议修订模式 redline）须跨文件对齐同一套分级与底线。
