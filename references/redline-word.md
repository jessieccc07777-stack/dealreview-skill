# 交付二 · Word 修订模式 redline（技术方法）

> 配套 `SKILL.md` 第 5 步「交付两成果」之成果二，以及 `deliverables.md`。
> 本文件说明如何把《风险审查报告》中的"修订条款"**直接落到客户上传的原协议 docx 上，
> 以 Word 的修订模式（track changes）呈现**，让用户打开后看到真实的增删标记，最后把关。

## 为什么用"真实修订模式"而不是"批注版报告"

用户要的是：AI 直接在 Word 文档里用修订模式改，用户最后把关。
- 修订模式 = OOXML 的 `w:ins`（插入，下划线）/ `w:del`（删除，删除线）节点。
- 在 Word「审阅 → 显示标记」下，用户能逐项接受/拒绝，**比一张批注表更贴近真实谈判 redline**。
- 因此成果二不再是"逐条批注表 docx"，而是**客户原协议的修订模式副本**。

## 方法（已验证）

技能自带脚本 `scripts/redline_word.py`（纯 python-docx + 原始 OOXML，无联网、无私有路径、不含任何立场）。

运行时由 AI 调用：

```python
import sys
sys.path.insert(0, "<skill>/scripts")
from redline_word import apply_redline

# replacements = 《风险审查报告》中所有"需修改条款"的 (原条款文本, 修订后条款文本)
replacements = [
    ("创始人应以全部个人财产为限向投资人支付回购价款……",
     "创始人（甲方）有义务以届时所持目标公司股权为限向投资人支付回购价款……"),
    ("反稀释调整采用完全棘轮方式……",
     "反稀释调整仅采用广义加权平均方式……"),
    # ……报告中每一条 🔴/🟠/🟡 的修订条款都对应一对
]

res = apply_redline("客户协议.docx", replacements,
                    out_path="客户协议_修订模式.docx")
print(res)   # {'applied': [...], 'not_found': [...]}
```

### 行为约定
- **输入**：客户上传的原协议 docx（务必另存副本，不改原件）。
- **输出**：`客户协议_修订模式.docx`，开启修订模式即可见每处增删。
- `new_text` 为空字符串 `""` → 表示**整段删除**该条款（只留 `w:del`）。
- 默认替换文档中**第一次**出现的 `old_text`（条款通常唯一）；如需全部替换传 `replace_all=True`。
- 若某 `old_text` 未找到，`not_found` 会列出，AI 应回报告说明并人工定位（可能是跨段/格式差异），不要用错误文本硬改。
- 跨 run、表格内段落均已验证可处理；**跨多个段落的条款请逐段分别给定 (old, new)**。

### 批注（可选增强）
- 修订的"理由与可接受底线"主载体是《风险审查报告》（含修订依据）。
- 若运行环境支持（如 `tencent-local-office-edit` / editor_sdk 的 `doc_insert_comment`），可在关键修订处再加一条 Word 批注，三五行说明"为何这样改 + 可接受底线"；不支持则跳过，报告已完整承载理由。
- **🟢 放行条款不改**，不在 redline 中动，仅在报告中说明"已核对、属市场惯例、放行"——不消耗谈判火力。

## 接收与交付
- 用户上传协议后，AI 先做第 1–4 步，产出《风险审查报告》（含五段式 + 修订依据 + 🟢放行清单）。
- 再从报告抽取所有"需修改条款"的 `(old, new)`，调用 `apply_redline` 生成修订模式 docx。
- 两份成果一并交付：① 风险审查报告（md / docx） ② 协议修订模式 docx。
- 用户最后在 Word 中逐项接受/拒绝并把关。
